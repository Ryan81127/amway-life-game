# 足球轉播看板 2.0｜積分、戰意與盤口觀察

開發分支：`football-2.0`（尚未合併到 `main`，正式網站不受影響）

## 1. 既有架構（實際檢查結果）

- Repository：`ryan81127/amway-life-game`；`main` 一有 push，`.github/workflows/pages.yml` 就把整個 repo 部署到 GitHub Pages。
- `football/` 是純前端：`index.html` 依序載入 20 多個 JS 檔，共用全域函式，沒有打包、沒有後端、沒有金鑰。
- 進入點 `app.js`：`render()` → `renderSchedule()`（賽程）或 `renderMatch()`（單場）。`lib.js` 把 ESPN 回應整理成 `model`；每 5 秒打一次比分端點偵測變化。
- 既有單場頁是一個長頁面，加上左側固定導覽與搜尋。

## 2. 資料來源盤點（2026-11-16 實測）

| 需求 | ESPN 端點 | 結果 |
|---|---|---|
| 賽程、即時比分 | `site/v2/sports/soccer/{league}/scoreboard` | 可用（日期區間參數會回 400，逐日抓） |
| 單場資料 | `…/{league}/summary?event=` | 可用；友誼賽常沒有技術統計 |
| 積分榜 | `apis/v2/sports/soccer/{league}/standings` | 可用：英超、歐冠聯賽階段、歐國聯 14 組、世界盃（含 `?season=2022`）；每個名次附區域說明 |
| 球隊已賽結果／未賽賽程 | `…/{league}/teams/{id}/schedule`（`?fixture=true`） | 可用 |
| 賠率 | summary 內的 DraftKings 讓球、大小、勝平負 | 只有單一來源、沒有歷史賠率 |
| 角球／罰牌／半場／單邊盤口 | 無 | **沒有可靠來源** |
| 傷停 | 無（足球多數賽事為空） | **沒有可靠來源**，沿用既有的名單比對推測 |
| 裁判、教練賽前發言 | 無 | **沒有可靠來源** |

沒有來源的項目一律顯示「資料不足」。之後若要接其他資料商，只需替換 `standings.js` 的抓取函式（輸出格式固定）。

## 3. 新增模組

| 檔案 | 對應模組 | 內容 |
|---|---|---|
| `rules.js` | competitionRules | 各賽事各賽季的積分、同分比較順序、目標名次、兩回合與點球判定、ESPN 區域說明解析 |
| `qualify.js` | qualificationEngine／liveQualificationEngine | 排名表、數學確定晉級／淘汰（枚舉所有勝平負組合）、大型聯賽上下界、下一球影響、還差幾球 |
| `standings.js` | standingsService | ESPN 積分榜、同組賽程與即時比分、手動修正比分（模擬）、與官方積分核對 |
| `motivation.js` | motivationAnalyzer | 兩隊戰意：每句標「事實／計算／推測／資料不足」 |
| `commentary.js` | commentaryGenerator | 口播模板：5 種風格＋預設混合、15／30／60 秒、重新產生 |
| `marketpanel.js` | marketAnalysisEngine | 8 個盤口的觀察面板、市場隱含機率與抽水、校準樣本累積 |
| `v2tabs.js` | 介面 | 單場頁分頁：看板｜積分／出線｜戰意｜主播口播｜盤口觀察；第一屏形勢快報 |
| `tests/qualify.test.js`、`tests/smoke.test.js` | 測試 | 見第 6 節 |

既有檔案只改三處：`index.html`（多載入 7 個檔）、`app.js`（`renderMatch` 加分頁掛載點；重新渲染時保留段落展開狀態）、`styles.css`（新增樣式）。原本的單場頁完整保留在「看板」分頁。

`predictionHistory`、`oddsDataAdapter`、`matchEventMonitor`：既有的 `ledger.js`（賽前與滾球快照，記下後不覆寫）已涵蓋快照與對帳；跨場查詢頁列在第二階段。

## 5. 出線狀態的判定方式

- 小組（6 隊以內）：逐場抓同組賽程，把所有未賽（含進行中）比賽的勝／平／負組合全部跑過。同分一律用最保守假設，所以「數學上確定」不依賴同分比較。
- 狀態：數學上確定／數學上確定無緣／平局即可確定／贏球即確定／必須取勝／需要其他場次配合／已踢完等其他場次／仍有可能／資料不足。
- 「目前排前二」只會顯示為名次與區域，不會寫成確定晉級。
- 自行計算的積分若與 ESPN 官方榜不一致（賽程缺漏或扣分），所有判定改為「資料不足」。
- 大型聯賽：用「最多還能拿幾分」的上下界判定確定與否；本場結果後的名次只用積分、淨勝球、進球排序並註明。
- 世界盃最佳第三名需要跨組比較，目前列為資料不足。

## 7. AI 與成本

- 第一階段**不呼叫任何 AI API**，口播由模板產生，費用為 0，也沒有金鑰外洩風險。
- GitHub Pages 是純靜態網站，金鑰不能放在前端。第二階段若要 AI 改寫口播：另架一支 Serverless Function（Cloudflare Workers 免費額度每天 10 萬次請求即可），前端把 `cmFacts()` 產生的事實句送過去，後端呼叫 DeepSeek 或其他相容 API 改寫語氣，並限制「只能改寫、不得新增事實」。
- 費用估算（需以供應商當時價目為準）：每段口播輸入約 400 字、輸出約 150 字；一場比賽產生 50 段，用低價模型大約是新台幣 1 元以內的量級。
- 風險：ESPN 是非官方公開端點，可能改版或限流（既有看板已有快取與重試）；規則每季可能調整，`rules.js` 需要每季複核。

## 8. 分階段計畫

1. **第一階段（本分支，已完成）**：積分榜、同分規則、出線形勢、同組連動與手動修正、戰意分析、口播產生器、盤口觀察面板、測試。
2. **第二階段**：世界盃最佳第三名跨組比較；兩回合淘汰賽頁面；賽程頁的聯賽積分榜入口；預測歷史查詢（依聯賽、盤口、時間）；半贏半輸分開統計；特一／特二時段設定。
3. **第三階段**：AI 改寫口播（Serverless）；其他資料來源 Adapter（多家賠率、傷停、裁判）。
